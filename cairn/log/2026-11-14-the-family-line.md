# The family line: the wizard leaves, the libraries follow

carillon joins the family release line in two commits. Spec moved: `daemon` (REMOVED: A first account is generated, never hand-written from scratch; ADDED: A first run points at the sample; MODIFIED: A watch runs from a TOML file, A pimdir calendar is watchable).

- Phase 1, the wizard leaves (098cef4, `feat!: drop the wizard, write the configuration from the sample`), on the libraries it was written against. src/wizard/ (13 files), the `configure` command and its `wizard` alias, the `wizard` feature and the io-pim-discovery dependency only it pulled, `config::render` and the `carillon-configure` schema are gone. A bare `carillon` prints the help, with a configuration or without one, and the missing-configuration failure moved from `Cli::execute` to `Config::load` and src/main.rs (cli-alignment-leftovers F6). tests/first_run.rs runs the built binary.
- Phase 2, the libraries (`build: move to pimalaya-cli 0.4, pimalaya-config 0.4, pimalaya-stream 0.4 and io-pimdir 0.12`). pimalaya-cli 0.4 (git 0be1b1f, feature `terminal`, the welcome needing nothing more; `spinner` stays off), pimalaya-config 0.4.1 from crates.io (its git pin dropped), pimalaya-stream 0.4, io-http 0.8, io-imap 0.10, io-jmap 0.9, io-msgraph 0.9, io-gmail 0.8, io-pimdir 0.12, dev io-oauth 0.7; io-webdav 185ab63, io-gcal dbb4481 and io-gpeople e4a9cac pinned in `[patch.crates-io]` beside ceichas until they release. clap's `env` feature went with `CARILLON_CONFIG`. `cargo tree -d --all-features -e normal` holds one pimalaya-stream, io-http, io-oauth and io-pimdir.
- `tls.cert` feeds `Tls::server`, mutual TLS left unset, its key unchanged. `TomlConfig` gains `sample_url` and `accounts` and loses `take_default_account`; `Config::load` wraps `TomlConfig::load`, so a missing configuration is pimalaya-config's `ConfigMissingError` ("No configuration found at <path>, start from the sample: <url>"). `check` and `watch -a` resolve the account through `take_account` and its `AccountError`, one wording for both (cli-alignment-leftovers F2): `check` naming an unknown account now lists the ones held, `watch -a default` takes the account marked default, and several defaults are refused.
- `-c` is pimalaya-cli's `ConfigFlags`: one path per flag, never split on `:`, `CARILLON_CONFIG` not read. config.sample.toml and the README say so, and now describe the default paths as layers, as pimalaya-config 0.3 already loaded them.
- src/main.rs meets a `ConfigMissingError` with pimalaya-cli's welcome when `welcome::is_wanted` (no `--json`, stderr a terminal), the sample found by `welcome::shipped_sample` or downloaded from its raw GitHub URL, the first command `check`; it exits 1. src/cli.rs builds the `Welcome`, as himalaya's and comodoro's do.
- io-pimdir 0.12 broke only the test fixtures' `PimdirAction::Remove`, which gained `if_match` and `resolves`. A pimdir watch reads draft-11 stores and refuses another draft through `PimdirReader::open`, naming the root.

Verified by `cargo test --all-features` (73 unit tests, 9 in tests/first_run.rs, the live suites built and ignored), `cargo clippy --all-targets -- -D warnings` over the default, all, empty and per-backend feature sets (rustls-ring with each of imap, jmap, maildir, dav, msgraph, gmail, gcal, gpeople, pimdir), and `sh cairn/verify.sh`. New tests: tests/first_run.rs, a `-c` path holding `:` named whole and `CARILLON_CONFIG` ignored, both failing against Phase 1's parser by its `value_delimiter` and `env`, and no welcome on a stderr that is no terminal; src/cli.rs, the welcome's download and copy commands; src/pimdir.rs, a store made through io-pimdir 0.12 watched by `pimdir::watch` with `alarm::run` until its alarm fires, which passes on io-pimdir 0.9 as well, being about the watch path rather than the draft. The welcome itself was seen once through `script` (a pseudo-terminal), not in a test. No draft-08 store was built to see its refusal, and no live suite was run: the owner runs them.

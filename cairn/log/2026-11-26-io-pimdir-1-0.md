# io-pimdir 1.0

carillon moves to io-pimdir 1.0.0, which follows pimdir storage-v1.0.0, sync-v1.0.0 and search-v1.0.0. A pimdir watch reads the storage-v1 stores neverest writes on it. A store any 0.x io-pimdir wrote (storage-draft-17 for carillon 1.0.0) is refused coded `store-version` and never migrated: its user syncs it until nothing is pending with the neverest that wrote it, moves it aside and lets a neverest on pimdir v1 sync a new one. There is no migration path from a draft store.

## What landed

- Cargo.toml: io-pimdir `version = "1.0.0"`, features unchanged, from crates.io; Cargo.lock moves io-pimdir's entry alone.
- src/pimdir.rs: the test helper `drain` unwraps `PimdirStore::for_source`, which now returns a `Result`. No other API carillon uses moved: `PimdirReader`, `PimdirFormatRefusal`, `sql::FORMAT_VERSION` (now `storage-v1`) and `PimdirError::code` keep their shape.
- src/error.rs: the `store-version` and `index-version` docs, shown in the `carillon-error` schema, name a version rather than a draft.
- tests/exit.rs: the refused store is storage-draft-17, the one carillon 1.0.0 read; a store asking to upgrade carillon is a storage-v2 one whose `read_version` is 2 (a `storage-draft-99` store now reads as earlier than storage-v1); a new case checks that a storage-v2 store whose `read_version` is 1 passes `account check`, which io-pimdir 0.20 refused.
- CHANGELOG.md: the Unreleased entry.

## Spec

- [daemon](../spec/daemon.md): "A pimdir calendar is watchable" reads storage-v1.0.0 through io-pimdir 1, reads a later store whose `read_version` is 1, and refuses a draft's store with the start-over wording (scenarios "A store a draft wrote" and "A later store a version 1 reader reads"); "A failure carries a stable code" words `store-version` for a draft or a later unreadable store.

## Left

- io-pimdir 1.0 adds the codes `source-empty` and `target-unsynced`; carillon, a reader, meets neither, and its relay table follows himalaya's, which does not list them yet.

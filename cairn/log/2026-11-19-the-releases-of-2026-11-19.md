# The releases of 2026-11-19

io-imap 0.12.0, io-sasl 0.3.0, io-pimdir 0.18.0, pimalaya-cli 0.7.0 and ical-rs 0.7.2 are taken from crates.io, no patch; Cargo.lock moves those five crates alone and `cargo tree` holds one io-sasl (0.3.0).

- io-imap: the `imap` feature enables `io-imap/std` where it enabled `io-imap/client`, the std runtime (`ImapClientStd`, its connect options) having moved to `std`; `std` pulls the new `client` feature, so the IDLE watch coroutines carillon drives build as before. `raw` returning bytes touches nothing carillon calls.
- io-sasl 0.3: `scram` enables the new `client` feature; no code moved.
- io-pimdir 0.18: additive, still draft-14; no code moved. The C5 helpers concern himalaya, cardamum and calendula, not carillon.
- pimalaya-cli 0.7: `CommonCode::RequestOrigin` makes the `carillon-error` schema admit `request-origin`, which carillon, with no `request` command, never raises. src/json_schema.rs `the_failure_code_is_typed_by_both_vocabularies` asserts it (fails on 0.6.1, which lacks the code). No exhaustive `match` on `CommonCode` here.
- ical-rs 0.7.2: its fixes are in JSCalendar conversion, which carillon never runs; no alarm moves.

Capabilities moved: daemon (the JSON contract, the pimdir backend).

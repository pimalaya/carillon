# Hooks run off the watch

Finding CRL-2 of the family analysis (~/.claude/plans/pimalaya-cli-family-analysis-2026-11-15/plan.md section 4.5), the owner's go of 2026-11-18 on the amended direction, and the JMAP push half of CRL-7 the coordinator added the same day. Spec moved: daemon (A hook failure never stops the watch, a paragraph and a scenario; A watch survives the change it reports, a sentence).

- `hook::run_command` ran the command inline with a blocking `.status()`, stdin inherited, so a hook sleeping 37 s hid the next arrival and held a SIGTERM until it ended, and an alarm hook running past the 15-minute grace made every alarm due meanwhile drop. `hook::run` and `hook::run_alarm` now show the notification and hand the command back as a `HookJob` (the command and its variables) in a `HookFired`; `WatchEvents` submits it to `hook::command::HookCommands`, which spawns it with `Stdio::null()` for stdin, its stdout on carillon's stderr as before, in a process group of its own on Unix, and reaps it from a thread of its own (`try_wait` every 100 ms), the failure sent as `hook-failed` once it ends.
- One instance per command of an account (the key is the account and the command): the firings while it runs wait in a FIFO, each with its own variables, and run one after the other, so two arrivals or two due alarms each run their command. A firing equal to one already waiting (same command, same variables, `HookJob: Eq`) is dropped; past 1000 waiting (`QUEUE`) a firing is dropped and counted, and the count is logged as a warning when the command ends or the watch stops. The first draft of this change kept one pending run with the last firing's variables, which lost all but the last of several arrivals or alarms; the coordinator ruled it out on 2026-11-18. The reaper starts the next waiting run on its next tick, so a queue drains at most ten runs a second per command. No timeout: the hook the analysis recommends (`neverest sync`) runs for minutes on a first sync. The optional per-hook `timeout` belongs to pimalaya-config's command table (cli-008), which another session handles; carillon reads none.
- On shutdown `WatchCommand::execute` calls `HookCommands::stop(HOOK_GRACE)` once the flag is set and the alarm threads are woken: SIGTERM to every running command's process group (`libc::kill(-pgid)`, the only `unsafe`, under `// SAFETY:`; `Child::kill` off Unix), the pending runs dropped, then up to one second for them to end, then SIGKILL to the process groups still alive and a blocking `wait` to reap them, as pimalaya-config's command spec has it (SIGTERM, then SIGKILL), with a warn line giving their count. Nothing is reported once stopping, so a hook ended by the SIGTERM prints no `hook-failed`. Clearing the running commands also drops the senders their reporters hold, so the event channel still closes once the account threads end.
- libc 0.2 becomes a direct dependency on Unix targets (`[target.'cfg(unix)'.dependencies]`); it was already in Cargo.lock, which only adds it to carillon's list.
- JMAP push: `jmap::subscribe` took every read deadline as a wakeup, so a stream gone dead (a resume, a network change) held the push watch until TCP gave up. It now notes when it last read a byte and, once nothing came for `PINGS_MISSED` (3) of the `ping` intervals it asked for, hands the stream back as ended, the loop opening a new one. A `ping` of 0 sets no limit.
- Tests: tests/watch.rs `a_slow_hook_holds_neither_the_watch_nor_its_shutdown` (a `sleep 30` hook, two arrivals, then SIGINT) and src/jmap.rs `an_event_stream_missing_its_pings_is_opened_again` (the loopback mock's event stream sending its head and nothing more) fail on the HEAD code (08b7555, built from a `git archive` snapshot: the second change waits for the hook, the stream read never ends) and pass after. src/hook/command.rs tests the failure report, the queue run in order with a duplicate dropped, the full queue's count, the null stdin, the shutdown's SIGTERM and its SIGKILL of a command ignoring SIGTERM; src/hook.rs `a_hook_hands_its_command_back_with_its_variables` replaces `a_failing_command_is_handed_back`, and the alarm command test now runs its job through `HookCommands`.
- Not built here: the `cfg(not(unix))` arms (`group`, `signal`), no Windows target being installed.

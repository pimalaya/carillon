# A refusal carries its code

carillon follows the family's failure contract in two commits. Spec moved: `daemon` (ADDED: A refused command line exits 2, A failure carries a stable code; MODIFIED: The account can be checked before it is watched, The JSON contract is described and versioned).

- Phase 1, the exit contract (45a2a4f, `feat!: a refused command line exits 2, a failed check exits 3`). src/main.rs parses through pimalaya-cli's `clap::parse` and reports through `ErrorReport::<ErrorCode>::eval_coded`, the failure going through `error::with_code` first; src/error.rs declares `ErrorCode` in every build. A refused line exits 2, under `--json` with the failure object coded `usage-invalid` on stdout. `check` rows are `{backend, ok, code, error}` and a failed row makes the command exit 3 after its report (`PartialOutcome`). The Ctrl+C notice of `watch` went from stdout to stderr. `carillon-error`'s `code` is typed by both vocabularies, `carillon-check` carries the row's `code`. tests/exit.rs runs the built binary.
- Phase 2, the codes (`feat: code a server's refusal and a store's`). `error::code` reads `code_of` else walks the chain over one reader per enabled backend, a `cfg`-gated slice of `fn` as neverest's: `imap::refusal_code` (`ImapClientError::status()`, `OVERQUOTA` and `NOPERM`), `dav::refusal_code` (neverest's reading adapted to the inner `WebdavSendError`, `WebdavSyncCollectionError` and `WebdavFollowRedirectsError` carillon's own pumps surface), `msgraph::refusal_code` (`send.api()`), `gmail`, `gcal` and `gpeople::refusal_code` over `error::google_code` (a copy of neverest's, with the parts of `google_refusal` a 403 is read by), `jmap::refusal_code` (io-jmap 0.9 keeps the status: `JmapSendError::HttpStatus` and `Request`, the session's `JmapSessionGetError::HttpStatus`, the event source's `JmapEventSourceError::HttpStatus`; 403, 429 and 507 coded) and `pimdir::store_code` through the `ErrorCode::of_pimdir` table. The IMAP resolver keeps the coroutine's error typed (as an `ImapClientError`) instead of `bail!("{err}")`, and the pimdir backend keeps the `PimdirError` as the cause of "Cannot open pimdir store at …", its text unchanged. `ErrorCode`'s `allow(dead_code)` is now per variant, on the builds where no reader raises it. `watch`'s "session lost" warning names the code when there is one. A dev-dependency on rusqlite 0.41 (the one io-pimdir links) restamps a store in a test.

Verified by `cargo test --all-features` (85 unit tests, 5 in tests/exit.rs, 9 in tests/first_run.rs, the live suites built and ignored), `cargo clippy --all-targets -- -D warnings` over the default, all, empty and per-backend feature sets (rustls-ring with each of imap, jmap, maildir, dav, msgraph, gmail, gcal, gpeople, pimdir), and `sh cairn/verify.sh`. New tests in Phase 2, each through the real error path and failing before it: the scripted IMAP server refusing EXAMINE with `NO [NOPERM]` (the watch, and the failure object `with_code` builds from it, coded `permission-denied`) and `NO [OVERQUOTA]` (the resolver, `quota-exceeded`); the scripted DAV server answering a bare 403 (on the sync report and on the calendar PROPFIND), a 403 naming `need-privileges` and a 507; Gmail's scripted stream answering a 403 `insufficientPermissions`, a 429 and a 403 `userRateLimitExceeded`; a JMAP session answered 403 and 429; `check --json` over a store stamped `storage-draft-08` printing the pimdir row coded `store-version` and exiting 3. The DAV 403 naming `valid-calendar-data` carries no code before and after, a guard rather than a regression test. Graph, Google Calendar and Google People have readers but no scripted test. No live suite was run: the owner runs them.
